# RFC 0003: 읽기 전용 D: 드라이브와 MSCDEX

- 상태: 제안
- 날짜: 2026-11-14
- 범위: `lib/dos_path.ml`(#55), `lib/dos_dos.ml`, `lib/dos_machine.ml`, INT 2Fh 배선(#116), `bin/dosboot.ml`, 새 `lib/dos_mscdex.ml`

## 왜

이 기계의 드라이브는 C: 하나다.

- INT 21h AH=19h(지금 드라이브)는 늘 2(C:)를 돌려준다.
- AH=0Eh(드라이브 고르기)는 DL을 보지 않는다.
- #55의 `Dos_path.parse`는 `D:` 로 시작하는 이름을 `Bad_drive`로 거부한다.
- INT 2Fh AX=1500h(MSCDEX 설치 확인)에는 아무도 답하지 않는다.

CD판 DOS 프로그램은 CD에서 데이터를 읽는다. RBIL INT 2F/AX=1500h에 따르면 이런 프로그램은 BX(CD 드라이브 수)와 CX(첫 드라이브 번호)로 CD를 찾는다. 그 드라이브의 파일은 INT 21h로 연다. 지금은 CD가 없다고 판단하거나, 찾은 드라이브를 열지 못한다.

로컬에는 CD판 게임이 없다. 어느 게임이 이 RFC로 돌기 시작하는지는 잴 수 없다. 그래서 목표는 RBIL과 DOSBox-staging 동작에 맞춘 COM 테스트로 잰다.

## 목표

1. 드라이브가 둘이다. C:는 지금처럼 읽고 쓴다. D:는 호스트 디렉터리 하나를 읽기 전용으로 보인다.
2. 지금 드라이브와 드라이브마다의 현재 디렉터리가 있다. INT 21h의 이름·FCB·드라이브 번호 인자가 D:를 가리킬 수 있다.
3. D:에 쓰려는 호출은 DOSBox-staging `cdromDrive`처럼 에러 05h(접근 거부)로 끝난다.
4. INT 2Fh AX=1500h·150Bh·150Ch·150Dh·1501h가 D:를 CD 드라이브로 알린다. AX=1510h(장치 요청)는 데이터 CD 하나가 들어 있는 드라이브처럼 답한다.
5. 바뀌지 않는 것:
   - `--cdrom`을 주지 않으면 D:는 없다. INT 2Fh AX=15xxh에도 지금처럼 아무도 답하지 않는다.
   - 삼국지3 프레임과 시나리오(스텝 수, 세이브 해시)가 같다.

## 하지 않는 것

- **ISO 9660 이미지.** 섹터 단위 호출(AX=1505h VTOC, 1508h 절대 읽기, 장치 요청 80h 읽기)은 이미지가 있어야 뜻이 있다. 이 RFC에서는 에러로 답한다. DOSBox-staging의 디렉터리 마운트(`CDROM_Interface_Fake`)는 성공으로 답하고 버퍼를 건드리지 않는다. 빈 버퍼를 읽은 데이터로 믿게 하지 않으려고 이 RFC는 다르게 한다.
- **CD 오디오.** 데이터 트랙 하나만 있는 CD로 답한다.
- **CD 바꾸기**(미디어 바뀜 신호), 드라이브 셋 이상, CDS(INT 21h AH=52h 목록의 현재 디렉터리 구조) 항목, INT 21h AH=32h·AX=440Dh.

## 근거

- RBIL(ctyme.com, 2026-11-14 확인): INT 2F/AX=1500h, 1501h, 1505h, 1508h, 150Bh, 150Ch, 150Dh, 1510h.
- DOSBox-staging `src/dos/dos_mscdex.cpp`, `drive_local.cpp`(`cdromDrive`), `dos_ioctl.cpp`, `cdrom.cpp`·`cdrom.h`(`CDROM_Interface_Fake`). main 브랜치, 2026-11-14에 받음.

| 호출 | RBIL | DOSBox-staging |
|---|---|---|
| AX=1500h BX=0 | BX = CD 드라이브 수, CX = 첫 드라이브(0 = A:) | 같다. AL=FFh도 쓴다 |
| AX=1501h | ES:BX에 드라이브마다 5바이트(subunit, 장치 헤더 far 포인터) | 장치 헤더 이름은 `MSCD001 ` |
| AX=150Bh CX=드라이브 | BX=ADADh, AX = 0(아님) 또는 0 아님 | CD면 AX=5AD8h |
| AX=150Ch BX=0 | BH.BL = 버전 | 2.23(BX=0217h) |
| AX=150Dh | ES:BX에 드라이브 번호를 1바이트씩 | 같다 |
| AX=1510h | CX = 드라이브, ES:BX = 장치 요청 헤더. 드라이버를 불렀으면 CF=0, 아니면 CF=1·AX=000Fh(잘못된 드라이브) | 요청 헤더 +3에 상태 워드를 쓴다 |
| AX=1505h·1508h | 실패하면 CF=1, AX = 15(잘못된 드라이브) 또는 21(준비 안 됨) | 디렉터리 마운트에서 1508h는 성공하고 버퍼는 그대로다. 1505h는 버퍼에 `CD001`·`CDROM`이 없으면 CF=1이다(BAD_FORMAT) |
| AX=1100h | — | 스택 [SP+6]이 DADAh면 ADADh로 바꾸고 AL=FFh(네트워크 리디렉터 확인) |

DOSBox-staging `cdromDrive`가 D:에 하는 일:

| 호출 | 결과 |
|---|---|
| 열기(AH=3Dh) 읽기 | 연다 |
| 열기 읽기·쓰기 | 읽기 전용으로 바꿔 연다 |
| 열기 쓰기 | 05h |
| 파일 만들기·지우기·이름 바꾸기, 디렉터리 만들기·지우기 | 05h |
| 속성 읽기(AX=4300h) | 읽기 전용(01h)을 세우고 보관·시스템 비트를 지운다 |
| AX=4408h(떼어낼 수 있나) | CF=1, 에러 01h(잘못된 기능 번호). `dos_ioctl.cpp`는 C: 이후 드라이브가 떼어낼 수 있으면 이렇게 답한다 |
| AX=4409h(원격인가) | DX=1000h(bit 12 = 원격) |

DOSBox-staging 디렉터리 마운트의 CD 정보(`cdrom.cpp` `CDROM_Interface_Fake`):

- 트랙 1-1, 리드아웃 60:00:00. 볼륨 크기(IOCTL 입력 08h)는 리드아웃에서 계산해 60 × 60 × 75 = 270,000 섹터다.
- 트랙 1은 00:02:00에서 시작하고 속성은 60h(데이터, 복사 허용)다.
- 오디오 재생·멈춤·이어 재생은 성공으로 답한다.
- 모르는 장치 명령은 로그만 남기고 에러 비트 없이 끝남 상태를 쓴다.

## 설계

### 드라이브 모델

```ocaml
type drive = C | D
```

- 닫힌 합타입이다. 문자열이나 정수로 갈라 보지 않는다.
- DOS 드라이브 번호는 두 가지다. 이 타입과 번호는 한 곳에서만 바꾼다.
  - 0부터: AH=0Eh·19h, MSCDEX CX. C: = 2, D: = 3
  - 1부터(0 = 지금 드라이브): AH=36h·47h DL, FCB 0바이트. C: = 3, D: = 4
- `Dos_path.t`가 드라이브를 가진다. `parse`는 `C:`·`D:`를 받는다. 다른 글자는 지금처럼 `Bad_drive`다. 드라이브를 빼면 지금 드라이브다.
- 현재 디렉터리는 드라이브마다 하나다. 지금 드라이브는 `C`로 시작한다.
- `--cdrom`이 없으면 D:는 없는 드라이브다. D:를 가리키는 호출은 C:가 아닌 다른 글자와 같은 에러로 끝난다.

| 호출 | 바뀌는 것 |
|---|---|
| AH=0Eh | DL이 C:·D:면 지금 드라이브를 바꾼다. AL = 드라이브 수(LASTDRIVE). 이 값은 아래 「결정할 것」에서 정한다 |
| AH=19h | 지금 드라이브 번호 |
| AH=36h·47h | DL(0 = 지금, 3 = C:, 4 = D:)을 본다. D:의 빈 클러스터는 0이다 |
| AH=3Bh·4Eh·3Dh 등 이름을 받는 호출 | `Dos_path.parse`가 드라이브를 정한다 |
| FCB 호출 | FCB 0바이트 드라이브(0 = 지금, 3 = C:, 4 = D:) |
| AH=29h | 이름 앞의 `D:`를 FCB 드라이브 바이트로 옮긴다 |
| AX=4408h·4409h | D:는 DOSBox처럼 4408h가 에러 01h, 4409h가 DX=1000h다 |

### D:의 내용

- `--cdrom DIR`로 호스트 디렉터리 하나를 받는다. C:처럼 부팅할 때 메모리 표로 읽는다. 실행 중에는 호스트를 다시 보지 않는다. 같은 입력이면 같은 결과가 나온다.
- 이름은 #55의 8.3 규칙을 지난다. 8.3으로 못 바꾸는 이름은 적재 단계에서 에러로 멈춘다. 몰래 건너뛰지 않는다.
- 볼륨 이름은 `--cdrom-label NAME`으로 받는다. 없으면 볼륨 이름이 없다. AH=4Eh 속성 08h가 이 이름을 찾는다.
- 스냅숏은 D: 내용을 담지 않는다. D:는 입력이고 C:와 달리 바뀌지 않기 때문이다. 지금 드라이브와 D:의 현재 디렉터리는 담는다. 그래서 형식 번호가 바뀐다.

### MSCDEX

- 새 `Dos_mscdex` 모듈이 AX=15xxh를 받는다. INT 2Fh 진입은 #116의 배선을 쓴다.
- 장치 헤더(18바이트, 이름 `MSCD001 `)는 ROM에 둔다. 자리는 다른 PR이 쓰지 않는 F000 오프셋으로 단계 3에서 정한다.
- AX=1505h·1508h는 CF=1, AX=0015h(준비 안 됨)로 답한다.
- AX=1510h 장치 요청은 명령마다 닫힌 합타입으로 나눈다. 모르는 명령은 상태 8103h로 답한다. bit 15는 에러, bit 8은 끝남, 03h는 알 수 없는 명령이다(RBIL INT 2F/AX=0802h 표 02596·02598). DOSBox와 다르다. 받지 않은 명령을 성공으로 보이지 않으려는 것이다.

| 명령 | 답 |
|---|---|
| 03h IOCTL 입력 00h | 장치 헤더 주소 |
| 03h IOCTL 입력 06h | 장치 상태 0314h(DOSBox와 같다). bit 2 raw·쿠킹 읽기, bit 4 오디오 읽기, bit 8 오디오 제어, bit 9 레드북·HSG 주소. 문 열림·잠김·재생 중·CD 없음 비트는 0이다 |
| 03h IOCTL 입력 07h | 섹터 크기 2048(쿠킹) |
| 03h IOCTL 입력 08h | 볼륨 크기 270,000 섹터(DOSBox와 같다) |
| 03h IOCTL 입력 09h | 미디어 바뀜 = 1(안 바뀜) |
| 03h IOCTL 입력 0Ah | 트랙 1-1, 리드아웃 60:00:00 |
| 03h IOCTL 입력 0Bh | 트랙 1: 00:02:00, 속성 60h |
| 03h IOCTL 입력 0Fh | 오디오 상태: 재생 안 함 |
| 0Ch IOCTL 출력 01h·02h | 받는다(문 잠그기, 리셋) |
| 0Dh·0Eh | 받는다(장치 열기·닫기) |
| 80h·82h 읽기 | 상태 8108h(섹터 없음, 표 02598 08h) |
| 84h 오디오 재생·85h 멈춤·88h 이어 재생 | 「결정할 것」에서 정한다 |

## 단계

PR 하나는 9파일 이하다. 단계마다 COM 테스트, 일부러 망가뜨리기, 삼국지3 프레임·시나리오로 확인한다.

1. **드라이브 타입**(base #55): `drive`, 드라이브를 가진 `Dos_path.t`, 지금 드라이브, 드라이브마다의 현재 디렉터리. D:는 아직 없다.
   → 확인: AH=0Eh·19h·47h·3Bh가 C:에서 지금과 같다. `D:X`는 없는 드라이브 에러다. AH=0Eh DL=3은 지금 드라이브를 바꾸지 않는다.
2. **D: 적재**: `--cdrom DIR`, `--cdrom-label`, 읽기 전용 에러, 속성, AX=4408h·4409h, AH=36h, FCB 드라이브 바이트, 스냅숏 형식.
   → 확인: 위 DOSBox 표의 일곱 줄을 COM 테스트 하나씩으로 맞춘다. D:에 쓰려는 호출 뒤 D: 표가 바이트 하나도 바뀌지 않는다.
3. **MSCDEX 찾기**(base #116): AX=1500h·150Bh·150Ch·150Dh·1501h·1100h, ROM 장치 헤더.
   → 확인: `--cdrom`이 있을 때와 없을 때를 둘 다 시험한다. 없으면 INT 2Fh 결과가 지금과 같다.
4. **장치 요청**: AX=1510h와 위 명령 표, AX=1505h·1508h 에러.
   → 확인: 명령마다 상태 워드와 버퍼 바이트를 시험한다. 잘못된 드라이브는 CF=1·AX=000Fh이고 헤더가 그대로다.

## 결정할 것

1. **AH=0Eh의 AL(드라이브 수).** MS-DOS는 LASTDRIVE(기본 E:, 5)를 돌려준다. 지금은 `default_drive + 1` = 3이다. D:가 생기면 4로 올릴지, MS-DOS 기본 5로 둘지 정해야 한다.
2. **오디오 재생 명령.** 데이터 트랙만 있으므로 에러로 답할 수 있다. 반대로 DOSBox처럼 성공으로 답할 수도 있다. 앞쪽은 데이터 CD를 넣은 드라이브에 가깝다. 뒤쪽은 음악 재생이 실패하면 멈추는 프로그램을 살린다. 그런 프로그램이 있는지는 확인하지 못했다.
3. **D: 글자.** D:로 고정할지, `--cdrom-drive`로 받을지 정한다. 이 RFC는 고정을 제안한다. 타입이 `C | D` 둘뿐이라 잘못된 상태가 생기지 않는다.

## 위험

- #55가 병합되기 전에는 단계 1을 시작할 수 없다. #55는 `Dos_path`를 처음 만든다.
- 단계 1은 이름을 받는 INT 21h 호출 전부를 건드린다. 열린 PR 가운데 INT 21h 파일 호출을 고치는 것(#79·#84·#93·#94·#97·#129·#130 등)과 충돌한다. 병합 순서 이슈 #96에 단계 1의 자리를 정해야 한다.
- D: 내용이 크면 부팅이 느려진다. CD 한 장은 650MB까지다. 메모리 표에 다 읽는 대신 첫 읽기 때 호스트 파일을 여는 방식은 결정론을 깨지 않는다. 호스트 파일이 실행 중에 바뀌지 않는다는 전제가 있어야 한다. 단계 2에서 크기를 재고 정한다.
