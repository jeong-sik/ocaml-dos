# RFC 0007: VESA BIOS 확장(VBE)

- 상태: 제안(보류 — 구현하지 않는다, 다시 볼 조건은 맨 끝)
- 날짜: 2026-11-21
- 범위: `lib/dos_bios.ml` 의 INT 10h, `lib/dos_video.ml` 의 비디오 메모리
- 앞선 RFC: 0004(DOS 구조), 0005(386 보호 모드)

## 지금 상태

INT 10h 에서 AH=4Fh(VBE 함수)는 처리하는 곳이 없다. `lib/dos_bios.ml:914` 의
`| _ -> report_unserved t No_function ~vector:0x10` 으로 떨어지고, 이 함수는
알림 훅만 부른다. 레지스터는 바뀌지 않는다. AX=4F00h 로 부른 게임은 AX=4F00h 를
돌려받는다. VBE 규격에서 성공은 AX=004Fh 이므로, 게임은 "VBE 없음"으로 읽는다.

## 조사 결과

classicdosgames.com 에서 받은 419개 게임(실행 파일 626개)을 gprobe 로 3천만
스텝씩 입력 없이 돌린 결과 파일을 합쳤다(2026-11-21, 이 저장소 밖
`~/me/.tmp/ocaml-dos-loop/survey/results*.tsv`).

- INT 10h AH=4Fh 를 부른 게임은 9개다. 결과 줄 19개에 AX=4F00h(컨트롤러 정보),
  1개에 AX=4F03h(현재 모드 얻기)가 적혀 있다. 두 함수 모두 미지원으로 읽힌다.
- 9개 가운데 8개는 3천만 스텝 뒤에도 돈다. 모드는 13h 가 3개, 12h 가 2개,
  03h 가 3개다. VBE 없이 VGA 모드로 물러선다. 나머지 하나(Charlie the Duck)는
  그때 예외로 끝났고, 지금 main 의 스모크에서는 03h 로 돈다.
- VBE 를 소프트웨어로 제공하는 TSR(`UNIVBE.EXE`, Taking Care of Business 에
  들어 있다)은 AX=4F00h 를 부른 뒤 종료 코드 254 로 끝난다. 게임이 아니다.
- VBE 가 없어서 멈춘 게임은 이 조사에서 찾지 못했다. 결과 파일에 남긴 화면 글
  (행마다 앞 140자)에도 VESA 를 요구한다는 문구는 없다. 입력 없이 3천만 스텝만
  돌렸으므로, 메뉴를 지난 뒤에 VBE 를 확인하는 게임은 보이지 않는다(확인 필요).
- 이 표본은 셰어웨어와 프리웨어에 치우쳐 있다. 상용 게임에서의 비율은
  모른다(확인 필요).

## 선택지

1. 구현하지 않는다(이 RFC 의 결정).
2. 최소 VBE 1.2: AX=4F00h(컨트롤러 정보)와 4F01h(모드 정보)만 답하고 모드 목록을
   비워 둔다. 게임이 모드를 고르지 못하므로 지금과 같은 VGA 물러서기를 탄다.
   얻는 것은 "VBE 있음, 모드 없음" 을 가정하는 게임이 있을 때의 진입 경로뿐이다.
3. 모드 하나 이상 지원: 4F02h(모드 설정), 4F05h(뱅크 전환)를 넣는다.

## 선택지 3 의 비용

비디오 메모리는 64KB 판 4장으로 모두 256KB 다(`lib/dos_video.ml` 의 `plane_size =
0x10000`, `plane_count = 4`). 모드별로 화면이 필요한 바이트는 가로 × 세로 ×
(256색이면 1바이트, 16색이면 4판에 나뉘어 판마다 1/8바이트)다.

| VBE 모드 | 해상도·색 | 필요한 바이트 | 256KB 에 들어가는가 |
|---|---|---|---|
| 100h | 640×400, 256색 | 256,000 | 들어간다(262,144 안) |
| 101h | 640×480, 256색 | 307,200 | 안 들어간다 |
| 102h | 800×600, 16색 | 판마다 60,000 | 들어간다 |
| 103h | 800×600, 256색 | 480,000 | 안 들어간다 |

256색 모드는 대부분 256KB 를 넘으므로, 모드를 넣으려면 비디오 메모리를 늘리고
뱅크 전환을 만들어야 한다. 스냅샷 형식도 따라 바뀐다(RFC 0002).
단점: 비디오 메모리를 늘리면 `Dos_snapshot` 크기가 함께 늘고, 지금 돌아가는
모든 VGA 모드의 시험을 다시 봐야 한다.

## 결정

구현하지 않는다. 이유는 둘이다.

- 부른 게임 9개가 모두 VBE 없이 VGA 로 물러서고, 멈춘 게임이 없다.
- 선택지 2 는 얻는 것이 없고, 선택지 3 은 비디오 메모리 모델을 바꾼다.

## 다시 볼 조건

다음 중 하나가 측정되면 선택지 2 나 3 을 새 RFC 로 올린다.

- VBE 없음이 원인으로 멈추거나 화면이 깨진 게임이 하나라도 나온다. 확인법:
  `gprobe` 의 UNSERVED 줄에 `int 10h ax=4f..` 가 있고, 같은 게임의 화면이 비거나
  멈춘다.
- 메뉴를 지난 뒤 VBE 를 확인하는 게임을 입력 시나리오로 찾는다(위 "확인 필요").
- masc 의 사용자가 VBE 를 요구하는 게임을 실행한다.
